# Board Manager (`esp_board_manager`)

**What it is** — `espressif__esp_board_manager` is an Espressif component that reads `board_devices.yaml`, generates device-handle code at build time via `esp-bmgr-assist`, and provides a runtime registry so application code can acquire typed handles to peripherals without hard-coding GPIO or bus config.

**How we use it here** — Every peripheral (display, touch, audio DAC/ADC, SD card) is declared in `boards/waveshare/esp32s3_touch_amoled_1_75/board_devices.yaml`. Application code calls `esp_board_manager_get_device_handle(name, &out_ptr)` to receive a handle, then casts it to the appropriate device struct. The generated stubs live in `esp-claw/application/edge_agent/components/gen_bmgr_codes/`.

---

## Findings & gotchas

**[2026-05-21] `esp_board_manager_get_device_handle` writes the INNER handle — never double-deref**

`esp_board_manager_get_device_handle(name, &out)` writes the device's *inner* handle into `out`, not the `esp_board_device_handle_t` wrapper.

What happens inside (`esp_board_device.c`): the factory stores `*device_handle = handle->device_handle` — it deliberately strips the wrapper before handing out. So the out-ptr you receive is already a `dev_lcd_touch_i2c_handles_t*` (or `dev_audio_codec_handles_t*`, etc.) — cast it directly.

Wrong pattern (caused the CST9217 "must be initialized" spam in patch 0010):
```c
esp_board_device_handle_t *touch_h;
esp_board_manager_get_device_handle("lcd_touch", (void **)&touch_h);
esp_lcd_touch_handle_t touch = touch_h->device_handle;  // WRONG — double-deref
```

`esp_board_device_handle_t` has `device_handle` at offset 16 (the 5th struct member). The object returned is only 8 bytes (two pointers: `touch_handle` + `io_handle`). Reading offset 16 walks past the struct into heap garbage. The garbage pointer is non-NULL, so the `esp_lcd_touch.c:57 / :71` "must be initialized" guard fires on every poll.

Correct pattern:
```c
dev_lcd_touch_i2c_handles_t *touch_h;
esp_board_manager_get_device_handle("lcd_touch", (void **)&touch_h);
esp_lcd_touch_handle_t touch = touch_h->touch_handle;  // correct
```

The same double-deref caused the voice codec `LoadStoreError` crash (accessing the audio handle the same wrong way). Once `cap_gemini_live.c` was updated to cast directly to `dev_audio_codec_handles_t*`, the crash disappeared and codec handles showed RAM addresses (`0x3c24...`) instead of IRAM addresses (`0x420b...`).

Source: `esp-claw/application/edge_agent/boards/waveshare/esp32s3_touch_amoled_1_75/setup_device.c` (factory entry patterns); `cap_gemini_live.c:147-161` (correct cast usage post-fix).

**[2026-05-21] Generated files must be manually updated when `esp-bmgr-assist` does not re-run**

`components/gen_bmgr_codes/gen_board_device_config.c`, `gen_board_device_handles.c`, and `gen_board_info.c` are auto-generated by `esp-bmgr-assist`. When `esp-bmgr-assist==0.5.0` is pinned and it fails to detect a yaml change, these files are NOT regenerated automatically. You must re-run the tool by hand or delete and rebuild.

Source: `esp-claw/application/edge_agent/components/gen_bmgr_codes/gen_board_device_config.c:222` (CST9217 chip declaration confirming generation).

**[2026-05-21] `sdkconfig` must be deleted when adding a new device type**

`idf_ext.py` injects `board_manager.defaults` into `SDKCONFIG_DEFAULTS` only when no `sdkconfig` file exists. If a stale `sdkconfig` exists, the new `CONFIG_ESP_BOARD_DEV_*_SUPPORT=y` flags are silently ignored. See [build-toolchain.md](./build-toolchain.md) for the full procedure.
