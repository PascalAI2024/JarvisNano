# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

JarvisNano is plain ESP-IDF 5.5.4 firmware for a voice + round-display AI
assistant. The only release target is the **Waveshare
ESP32-S3-Touch-AMOLED-1.75C**: 466×466 CO5300 AMOLED, CST9217 touch,
ES8311/ES7210 audio, QMI8658 IMU, AXP2101 PMIC, 32 MB flash, 8 MB PSRAM.
Gemini Live runs through `jr_transport` (16 kHz uplink, native 24 kHz
playback); tools run through a JarvisMCP gateway behind a device-side allowlist.

The live image is **only** `main/` + `components/jr_*` + the selected
`boards/` YAML. `firmware/`, `esp-claw/`, `experiments/`, `dashboard/`,
`android/` are reference or future tracks and are not compiled into the v5
image. Edit those only when the task is explicitly about them.

## Commands

```bash
# Build (Docker, pinned espressif/idf:v5.5.4) → build/jarvisrobot_v5.bin
./scripts/build-v5.sh
RECONFIGURE=1 ./scripts/build-v5.sh     # regenerate sdkconfig from sdkconfig.defaults

# Flash over USB-JTAG (builds first unless NO_BUILD=1; DIO mode enforced)
./scripts/flash-v5.sh
# Flash over Wi-Fi while the firmware is running (esptool cannot sync then)
export JARVIS_DEVICE_HOST=<ip>; scripts/jarvisctl.py ota

# Host tests — no ESP-IDF needed
./scripts/host-tests.sh                 # both jr_display suites (hud + shell)
cd host && cmake -B build && cmake --build build && ./build/jr_host_tests   # jr_core + jr_dsp + jr_transport
cmake -S components/jr_tools/host -B build-tools-host && cmake --build build-tools-host && ctest --test-dir build-tools-host --output-on-failure
python3 -m unittest scripts/test_jarvis_desk.py

# Pre-commit gates
./scripts/check-secrets.sh
git diff --check
bash -n scripts/*.sh
```

Tests are Unity suites with no per-test filter: to run one test, run the
suite binary it lives in (`host/build/jr_host_tests`,
`components/jr_display/tests/build/jr_display_shell_tests`, …). Add a new
suite to `scripts/host-tests.sh`, not to a habit — a suite nobody runs once hid
eight failures.

`sdkconfig` is gitignored and regenerated by the build. **Any Kconfig change
(memory, PM, FreeRTOS stats) must go in `sdkconfig.defaults`** or it silently
disappears on the next reconfigure.

## Operating the device

With `JARVIS_DEVICE_HOST` set, `scripts/jarvisctl.py status|listen|mute|say|
screen|canvas|tune|taps|vadlog|reboot|ota` drives the device. `status` exits
non-zero when the device is deaf or muted: check it before treating "no
response" as a firmware bug. `scripts/gesture-doctor.py` reads the touch
counters; ask the device before reading source for input questions. Serial is
single-owner: kill any monitor before flashing.

`JR_DEV_OPEN_DIAGNOSTICS` in `main/main.c` opens the debug routes without
pairing during development and **must be 0 before a release**.

OTA images boot into a ~45 s probation. A reboot through the bootloader during
probation (deep sleep, PMIC power-off, reset) rolls the image back; the code
refuses those while `image_in_probation()`.

## Architecture

Read `docs/ARCHITECTURE.md` for the diagrams; the invariants that shape every
change are:

- **`main/main.c` is the composition root** (large, single file). It owns all
  concrete wiring: tasks, the HTTP control plane, the 1 Hz shell publish, the
  mood/rest ladder decisions, deep sleep, persona text, and the privacy gate.
  Feature work usually lands as a pure piece in a `jr_*` component plus wiring
  here.
- **`jr_core` and `jr_dsp` are pure.** They call no ESP-IDF, driver, network,
  or display API and compile on the host with a plain compiler
  (`host/CMakeLists.txt` enforces this by having no IDF include path). Hardware
  reaches them only through `jr_ports/*` interfaces and fakes in `host/fakes`.
  `jr_transport` (Gemini framing/parsing) is host-testable too; only its
  ws adapter touches IDF.
- **One owner per realtime resource.** `jr_voice` runs the orchestrator step,
  Gemini events, input policy, ladder, privacy, and the sleep decision.
  `websocket_task` handles transport only. `jr_pb_feed` drains the playback
  ring. `gfx_render` is the **only** task that may issue a panel command
  (brightness, DISPOFF, SLPIN): requests are flagged and applied inside
  `panel_flush`. `httpd` posts bounded commands and never owns realtime state.
- **Cross-task state is lock-free packed words** in `jr_display` (`s_power_word`,
  `s_links_word`, `s_ota_word`, nav word). Add bits to a word; do not add a
  mutex. Shell tests pin the bit layouts.
- **The display has no canvas and no runtime CPU buffers.** Faces are EAF
  assets via `esp_emote_gfx`; the ring/sheet UI is one procedural compositor
  rendering 12-row strips. See `docs/reference/display-emote-gfx.md` and
  `docs/GLASS_DESIGN.md` before drawing anything.
- **Tools are a generated JS template.** `components/jr_tools/src/
  jr_tools_templates.c` holds `JR_TOOLS_EXEC_JS` (allowlist, deny prefixes,
  named-vs-positional calling). Regenerate the whole line from a script rather
  than hand-editing escaped JS. Results are projected to fit
  `JR_TOOLS_CODE_CAP`; a 7 KB result is a bug.
- **Power is a ladder, not a scheduler.** `jr_mood` (pure) decides AWAKE →
  AMBIENT → WHISPER → DREAM from stillness and battery saver; `main.c` adds the
  world (USB, OTA, leases, uptime) and turns DREAM into deep sleep, modem sleep,
  and the 240/160 MHz CPU gears. `docs/reference/power-modes.md` has the
  measurements and the QMI8658 wake-on-motion gotchas.
- **Internal RAM's largest contiguous block is the binding constraint**, not
  total free heap. TLS dies under ~8 KB contiguous. Task stacks go in PSRAM;
  check `/api/diag/tasks` after adding any task or event lane.

## Docs and evidence

`docs/reference/` holds dated subsystem pages; start there before touching a
new area (board manager double-deref, `llm_profile` is a protocol enum, Gemini
Live API fields, NVS three-file registration, IMU interrupt routing). After a
research pass, add or update a page using `docs/reference/_TEMPLATE.md` with
`file:line` or URL citations; mark unverified links `(not fetch-verified)`.

`PLAN.md` is the actionable roadmap with acceptance gates; `docs/NEXT_SESSION.md`
is the handoff. `DOCUMENTATION_MAP.md` gives source-of-truth order when files
disagree (compiled source first). Screenshots and logs that prove a claim go in
`docs/evidence/` after redaction. A framebuffer mirror does not prove the panel
lit; a WAV tap does not prove the speaker was audible.

**Never put in this repo:** secrets, API keys, bearer tokens, internal URLs
(any `*.igddev.com` host or equivalent), Wi-Fi credentials, device MAC or IP
addresses, or other device-specific identifiers. Test fixtures use
documentation-range IPs (192.0.2.x, 198.51.100.x); `check-secrets.sh` flags
private ranges. Commit with explicit pathspecs.

## Legacy esp-claw overlay

`scripts/bootstrap.sh` builds the older esp-claw tree and is not the v5 image.
If you must touch it: it overwrites `esp-claw/` copies from `firmware/` and
`boards/` on every build, so edit the canonical sources, and files that exist
only in esp-claw are changed via idempotent `apply_*_patch` functions inside
`bootstrap.sh`. Full recipe in `docs/reference/build-toolchain.md`.
